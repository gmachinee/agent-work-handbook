# 문서 형식

## 기본 형식

정식 지식 문서는 UTF-8 Markdown(`.md`)으로 작성합니다. 파일 첫 줄부터 `---`로 구분한 YAML frontmatter를 두고, 본문은 하나의 `#` 제목과 `##`, `###` 소제목으로 구성합니다.

이 문서에서 정의하는 메타데이터는 이 저장소의 자체 계약입니다. 특정 RAG 제품의 전용 형식에 의존하지 않습니다.

파일명은 `test-product-contract.md`처럼 소문자 영문과 하이픈을 사용합니다. 제목과 본문은 한국어를 포함해 필요한 언어로 작성합니다.

## 필수 메타데이터

| 필드 | 자료형 | 기준 |
| --- | --- | --- |
| `id` | 문자열 | `kb-`로 시작하는 고유 식별자. 영문 소문자, 숫자, 하이픈으로 구성하며 이동·이름 변경 시 유지 |
| `title` | 문자열 | 문서의 질문 또는 주제를 구체적으로 표현. 본문의 `#` 제목과 일치 |
| `kind` | 문자열 | `rule`, `guide`, `reference`, `pattern` 중 하나 |
| `status` | 문자열 | `draft`, `active`, `archived` 중 하나 |
| `summary` | 문자열 | 무엇을 알려주는지 설명하는 1~2문장 |
| `scope` | 문자열 배열 | `general` 또는 `project:<name>`. 최소 하나의 범위를 기록 |
| `tags` | 문자열 배열 | 주제·기술·작업을 나타내는 태그. 초안은 빈 배열 허용 |
| `created` | 문자열 | 생성일. `"YYYY-MM-DD"` 형식 |
| `updated` | 문자열 | 내용 변경일. 생성일 이후 또는 같은 날짜 |

ID는 문서의 정체성입니다. 검색 조각과 관련 문서 관계는 경로 대신 ID를 기준으로 연결할 수 있습니다. ID가 겹치면 새 문서의 ID를 먼저 수정합니다.

폴더와 종류는 다음과 같이 맞춥니다.

| 폴더 | `kind` |
| --- | --- |
| `knowledge/rules/` | `rule` |
| `knowledge/guides/` | `guide` |
| `knowledge/references/` | `reference` |
| `knowledge/patterns/` | `pattern` |

보관 문서는 `archive/`로 이동하되 원래 `kind`를 유지합니다.

## 선택 메타데이터

```yaml
reviewed_on: "2026-10-14"
language: ko
sources:
  - title: 출처 제목
    url: https://example.com/article
    accessed_on: "2026-10-14"
related:
  - kb-related-document
supersedes:
  - kb-previous-document
```

- `reviewed_on`: 내용을 재검토한 날짜입니다. 파일 수정 날짜와 구분합니다.
- `language`: 주 언어입니다. 필요할 때 검색 언어 필터로 사용합니다.
- `sources`: 외부 출처 배열입니다. 각 항목에 `title`, `url`, `accessed_on`을 기록합니다. `published_on`은 확인 가능한 경우에만 추가합니다.
- `related`: 관련 문서의 ID 목록입니다. 본문에는 읽을 수 있는 상대 링크도 추가할 수 있습니다.
- `supersedes`: 이 문서가 대체하는 기존 문서의 ID 목록입니다. 대체된 문서는 보관 처리하고 연결된 링크를 정리합니다.

외부 자료를 바탕으로 작성한 문서에는 `sources`를 기록합니다. 외부 자료를 다루는 `reference`에는 최소 하나의 출처가 필요합니다. 개인 경험이나 직접 작성한 기준은 본문의 판단 근거 또는 검증 기록으로 출처를 설명합니다.

## 상태와 검토

| 상태 | 의미 | 기본 검색 |
| --- | --- | --- |
| `draft` | 작성 또는 검토 중 | 초안 조회 요청에서 활용 |
| `active` | 소유자가 현재 활용 대상으로 검토한 문서 | 포함 |
| `archived` | 사용을 마쳤거나 대체된 문서 | 과거 기록 조회 요청에서 활용 |

상태는 활용 여부를 표현합니다. `active` 참고 자료도 저자의 주장, 적용 조건, 한계를 가진 자료입니다. 채택한 작업 기준은 별도 `rule`로 작성합니다.

현재 대체 관계에서 같은 적용 범위의 규칙이 동시에 유효해지는 일이 없도록 정리합니다. 부분 대체라면 두 문서의 적용 범위와 본문 조건을 명확하게 수정합니다.

## 본문 구성

| 종류 | 권장 소제목 |
| --- | --- |
| `rule` | 적용 상황 / 기준 / 예외와 조건 / 적용 예시 / 판단 근거 / 관련 문서 |
| `guide` | 목표 / 준비 조건 / 작업 순서 / 완료 기준 / 문제 발생 시 대응 / 관련 문서 |
| `reference` | 출처 / 핵심 요약 / 내 해석 / 활용할 상황 / 한계와 확인 사항 / 관련 문서 |
| `pattern` | 문제 / 적용 조건 / 해결 방법 / 검증 방법과 결과 / 한계 / 관련 문서 |

조건이 없는 항목은 빈 제목을 남기기보다 제거합니다. 정식 문서에는 템플릿의 자리표시자를 실제 내용으로 바꿉니다.

## 검색과 재사용을 위한 작성 기준

- 한 문서는 하나의 질문, 작업, 기준 또는 패턴을 다룹니다. 같은 내용은 한 곳에 보관하고 다른 문서에서 연결합니다.
- 소제목은 구체적으로 씁니다. 긴 문서는 각 절을 읽어도 대상과 전제 조건을 이해할 수 있도록 작성합니다.
- 기준과 그 예외, 절차와 준비 조건, 코드와 설명은 함께 읽을 수 있게 배치합니다.
- 코드, 명령, 수치에는 필요한 버전·환경·적용 조건을 기록합니다.
- 원문의 주장과 개인의 해석을 서로 다른 절로 구분합니다.
- 링크에는 무엇을 확인할 수 있는지 설명합니다. 외부 URL만 저장한 자료도 핵심 요약과 활용 상황을 적습니다.
- 이미지와 첨부 자료에는 본문에서 설명과 상대 링크를 붙입니다.
- GitHub와 로컬 복제본에서 함께 읽을 수 있도록 저장소 내부 링크는 상대 경로로 작성합니다.

## 활성화 전 확인

필수 메타데이터, 고유 ID, 종류와 폴더의 일치, 실제 날짜, 적용 범위, 본문 내용, 출처 또는 판단 근거, 내부 링크를 확인합니다. 패턴은 검증 기록과 확인한 환경을 추가로 확인합니다. 문서가 공개될 수 있는지도 함께 검토합니다.
