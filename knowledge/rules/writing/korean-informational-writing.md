# 한국어 정보성 콘텐츠 작성·편집 지침

> **문서 상태:** 상위 작성 표준의 초안이다. 저장소에 문서를 추가한 것과 각 에이전트의 실행 지침에 적용한 것은 구분한다. 이 문서의 등록만으로 기존 실행 설정이나 작업별 지침이 바뀌지는 않는다.

## 1. 목적과 범위

정보성 글의 목적은 독자가 필요한 내용을 정확히 이해하고, 글의 목적에 맞게 판단하거나 행동하도록 돕는 것이다. 문법적으로 맞는 문장만으로는 충분하지 않다. 문장이 자연스럽더라도 의미 관계가 달라지거나 필요한 설명이 빠지면 고쳐야 한다.

### 적용 대상

- 공개 자료를 조사·가공해 작성하는 소개, 설명, 비교, 해설, 요약.
- 조직 내부에서 정보를 공유하는 보고, 안내, 검토 문서.
- 위 내용을 전달하는 뉴스레터, 카드뉴스, 웹 문서 등의 본문과 제목.

### 다루지 않는 것

- 모든 한국어 문서에 적용되는 국가·기관의 어문 표준을 제정하는 일.
- 제품 선별, 자료 수집 운영, 시장·트렌드 분석 방법, 예약 발행, PDF 디자인.
- 특정 서비스의 브랜드 말투나 특정 작업의 고정 양식.
- 계약·법령·안전 지침 등의 분야별 전문 검토를 대신하는 일.

이 문서는 기존 자료의 원칙을 정보성 글에 맞게 **선별하고 일반화한 지침**이다. 원전의 모든 규칙을 그대로 채택한 문서도, 새로운 한국어 문법 이론을 제시하는 문서도 아니다.

### 근거를 읽는 방법

- **근거:** 기존 자료에서 가져오거나 일반화한 원칙에는 해당 출처 번호를 붙인다.
- **자체 구성:** 이 저장소의 적용 범위, 원칙의 우선순위, 작성·검수 순서, 통과 기준은 이 지침을 위해 구성한 기준이다. 특정 원전의 완성된 체계로 소개하지 않는다.
- **편집 예시:** 아래 예시는 원전의 인용이나 실제 제품의 기능 검증 결과가 아니라, 오류를 설명하기 위해 작성한 가상 상황이다. 예시에서 정한 사실 관계를 전제로 비교한다.

서지 정보, 검토한 장·쪽, 채택한 내용과 가져오지 않은 규칙은 [출처 및 적용 범위](../../references/writing/korean-informational-writing-sources.md)에 기록한다.

## 2. 공통 표준과 작업별 지침의 관계

이 구분과 우선순위는 **자체 구성 기준**이다.

| 구분 | 정하는 내용 | 정하지 않는 내용 |
|---|---|---|
| 이 문서: 상위 작성 표준 | 문장 구성, 어휘, 의미·조건 보존, 명료한 설명, 독자 이해 | 브랜드 말투, 특정 작업의 분량·배치·선별 기준 |
| 작업별 작성 지침 | 독자와 목적, 설명 깊이, 말투, 제목·본문 구성, 매체별 길이 | 사실이나 조건을 바꾸는 예외 |

작업별 지침은 상위 표준을 반복해서 복사하기보다, **해당 작업에서 어떻게 적용할지**를 정한다. 예를 들어 Product Scout에서는 독자의 배경지식, 제품 설명의 깊이, 친근한 말투를 구체화할 수 있다. 수집·선별·발행 운영은 별도 지침에서 다룬다.

작업별 말투나 분량 요구가 의미·조건 보존과 충돌하면 의미와 조건을 보존한다. 짧게 쓸 수 없으면 두 문장으로 나누거나 구성을 바꾼다. 제한을 맞추려고 사실을 바꾸지는 않는다.

## 3. 작성 전에 정할 것

독자와 글의 목적에 따라 설명의 내용과 수준을 정한다. 직업이나 직함만으로 배경지식을 단정하지 않는다. 같은 개발자라도 특정 프로젝트나 기술을 얼마나 아는지는 다를 수 있다.[2][8]

다음 질문에 답한 뒤 쓴다. 질문의 배열은 **자체 구성**이며, 모든 글에 답변 양식을 출력하라는 뜻은 아니다.

| 질문 | 확인할 내용 |
|---|---|
| 누가 읽는가? | 구체적인 독자와 해당 주제에 관한 배경지식 |
| 왜 읽는가? | 이해, 비교, 판단, 실행 등 이 글을 읽는 목적 |
| 읽고 무엇을 알아야 하는가? | 반드시 전달할 핵심 내용과 필요한 설명 |
| 무엇이 확인되어 있는가? | 원자료에 있는 사실, 조건, 수치, 미확인 사항 |
| 어디에서 읽는가? | 독립된 카드, 긴 문서, 내부 보고 등 읽는 맥락 |

독자가 아는 내용은 반복 설명하지 않아도 된다. 반대로 전문 용어를 모르는 독자에게는 용어를 나열하기 전에 그 말이 가리키는 일을 설명한다. **설명량은 모든 독자에게 동일하지 않다.** [2][8]

## 4. 의미와 조건을 먼저 보존한다

### 4.1 자연스럽게 고치되 사실 관계를 바꾸지 않는다

영문 표현을 한국어 어순과 맥락에 맞게 재구성할 수 있지만, 의도한 의미를 훼손해서는 안 된다. 간결하게 고치는 경우에도 원문의 의미를 유지한다. Microsoft의 현지화 원칙을 한국어 정보성 글의 편집에 일반화한 기준이다.[5]

편집 전후에 다음이 같은지 비교한다. 점검 항목의 구성은 **자체 구성**이다.

- **주체:** 누가 하는 일인가?
- **행위와 대상:** 무엇을 하며, 무엇에 하는가?
- **방향과 위치:** 어디에서 처리하고, 어디로 보내거나 저장하는가?
- **결과:** 초안, 제안, 실행 결과 중 무엇을 얻는가?
- **범위:** 일부, 특정 요금제, 특정 환경, 선택한 방식에만 해당하는가?
- **조건:** 필수인가, 선택인가? 무엇이 선행되어야 하는가?
- **확실성:** 확인된 사실인가, 설명자의 주장인가, 가능성이나 추정인가?

### 4.2 필수·선택·예외를 구별한다

의무, 금지, 재량, 예외를 분명하게 표현한다. 이 원칙은 공공언어 지침에 제시되어 있으며, 여기서는 기능 설명과 일반 안내의 조건 보존에도 적용한다.[3]

| 원자료의 의미 | 보존할 표현의 예 | 피할 변화 |
|---|---|---|
| 반드시 거치는 단계 | 확인한 뒤 저장한다 | 확인은 선택 사항처럼 쓴다 |
| 필요할 때만 하는 일 | 필요하면 수정한다 | 항상 수정해야 한다고 쓴다 |
| 선택 가능한 기능 | 연결할 수 있다 | 기본으로 연결된다고 쓴다 |
| 일부 기능에 해당 | 일부 기능을 기기 안에서 처리한다 | 모든 기능이 기기 안에서 처리된다고 쓴다 |
| 초안이나 제안 제공 | 답변 초안을 제안한다 | 답변을 자동 발송한다고 쓴다 |

**편집 예시 — 확인은 필수, 수정은 선택인 상황**

- 부정확: `찾아낸 날짜를 확인하고 고친 뒤 저장합니다.`
- 수정: `찾아낸 날짜를 확인하고, 필요하면 수정한 뒤 저장합니다.`

`필요하면`은 장식이 아니라 행동 조건이다. 짧게 쓸 때도 남긴다.

### 4.3 설명을 보충할 때는 사실도 보충 확인한다

원자료에 동작이 설명되어 있지 않다면, 도구의 분류명이나 일반적인 작동 방식만으로 세부 기능을 만들어 넣지 않는다. 추가 자료에서 확인하거나, 확인한 범위만 설명한다.

이 항목은 **의미 보존을 위한 자체 구성 기준**이다. 문장 교정으로 해결할 수 있는 문제와 새로운 정보가 필요한 문제를 구별한다.

- `코딩 도구`라는 분류만으로 파일 수정·테스트 실행이 가능하다고 단정하지 않는다.
- `기기 내 처리`라는 표현만으로 자료가 외부로 전혀 전송되지 않는다고 단정하지 않는다.
- 제작자의 기능 설명을 옮긴 것과 직접 기능을 시험한 것을 구별한다.
- 근거가 부족한 내용을 자연스러운 문장으로 다듬었다고 해서 확인된 사실이 되지는 않는다.

## 5. 문장의 짜임과 의미 관계를 맞춘다

주어·목적어·부사어와 서술어의 관계, 대등한 연결, 수식 대상과 범위를 확인한다. 필요한 성분을 생략하거나 서로 다른 행위를 같은 서술어에 잘못 묶지 않는다.[1]

### 5.1 같은 문장에 다른 주체가 있으면 드러낸다

앞 문장의 주체를 다음 절까지 그대로 적용해도 되는지 확인한다. 주체가 바뀌거나 처리 위치와 수신 위치가 다르면 명시한다.[1][4]

**편집 예시 — 담당자가 메신저에서 답하고 고객은 웹 화면에서 받는 상황**

- 모호함: `고객은 웹에서 묻고, 답변은 메신저로.`
- 수정: `담당자는 메신저에서 웹사이트 문의에 답합니다. 고객은 웹 화면에서 답변을 확인합니다.`

제목에서 빠진 관계가 본문에 있다고 해도, 제목이 다른 뜻으로 읽히면 제목도 고친다.[2]

### 5.2 병렬로 묶는 요소를 같은 층위로 맞춘다

사람과 상황, 대상과 목적, 기능과 결과를 같은 종류인 것처럼 나열하지 않는다. 문법적인 형태뿐 아니라 실제 의미가 대등한지도 확인한다.[1]

**편집 예시 — 이용 대상과 사업 아이디어 참고 대상을 함께 설명하는 상황**

- 어긋남: `카드 이용자 또는 금융 서비스를 구상할 때 참고할 만합니다.`
- 수정: `카드 이용자나 금융 서비스를 구상하는 기획자가 참고할 만합니다.`

### 5.3 하나의 서술어로 묶을 수 있는지 확인한다

각 대상에 그 서술어를 따로 붙여 읽는다. 하나라도 뜻이 달라지면 서술어를 나누거나 문장을 분리한다. 이는 원전의 부당한 서술어 공유 문제를 점검하는 적용 방법이다.[1]

**편집 예시 — 자료 저장, 자료에 대한 질문, 자료를 이용한 초안 작성이 가능한 상황**

- 왜곡: `자료를 저장하고 질문·초안으로 바꿉니다.`
- 수정: `자료를 저장할 수 있습니다. 자료의 내용에 관해 질문하거나, 자료를 바탕으로 초안을 만들 수도 있습니다.`

### 5.4 수식 대상과 지시 대상을 분명하게 한다

- 수식어가 어떤 말에 붙는지 두 가지로 읽히면 위치를 바꾸거나 문장을 나눈다.[1]
- `이것`, `그것`, `이 방식` 등의 대상이 모호하면 구체적인 이름으로 바꾼다. 모든 지시어를 없애라는 뜻은 아니다.[7]
- `기기에서 문서를 읽고 정리하는 기능`이 어디까지 기기에서 실행되는지 중요하다면, 해당 행위별로 위치를 밝혀 쓴다. 이 예시는 수식 범위 점검의 자체 구성 사례다.

## 6. 용어보다 이해할 내용을 설명한다

### 6.1 분류명과 기능 목록만으로 설명을 끝내지 않는다

독자가 알아야 할 실제 동작을 설명한다. 추상적인 명사보다 구체적인 동사를 쓰면 행동과 관계를 드러내는 데 도움이 된다.[4][6]

주제에 따라 다음을 골라 설명한다. 모든 글에 같은 순서로 전부 넣는 양식은 아니다. 아래 구성은 **자체 구성**이다.

| 글에서 설명하는 대상 | 독자가 필요로 할 수 있는 내용 |
|---|---|
| 도구·서비스 | 누가 어떤 일을 맡기며, 도구가 무엇을 하고, 어떤 결과를 돌려주는가 |
| 변화·동향 | 무엇이 이전과 달라졌고, 구체적으로 어디에서 나타나며, 왜 관련 있는가 |
| 정책·내부 안내 | 누구에게 적용되고, 무엇이 달라지며, 언제 무엇을 해야 하는가 |
| 개념·기술 | 무엇을 뜻하고, 어떤 상황에서 쓰이며, 기존 방식과 어떻게 다른가 |

전문가 대상 글에서는 분류명으로 충분한 경우도 있다. 문제는 전문 용어의 존재가 아니라 **독자에게 필요한 설명을 용어가 대신하는 것**이다.[8]

### 6.2 추상적인 표현을 확인된 동작으로 푼다

**편집 예시 — 휴대전화에서 음성을 글로 바꾸는 기능을 설명하는 상황**

- 설명 부족: `AI 처리를 내 기기에서 하는 선택지가 있습니다.`
- 수정: `말을 글로 바꾸는 작업을 외부 서버가 아니라 휴대전화 안에서 처리할 수 있습니다.`

두 번째 문장은 예시에서 정한 처리 위치를 설명한다. 이것만으로 모든 기능의 오프라인 사용이나 외부 전송 차단까지 입증하지는 않는다.

### 6.3 예시는 설명을 돕되 사실을 대신하지 않는다

예시는 실제로 확인한 사용 방식이나 **가정임을 명시한 상황**으로 쓴다. 이해를 돕겠다는 이유로 확인되지 않은 성능이나 결과를 예시에 추가하지 않는다. 이 구분은 **자체 구성 기준**이다.

- `예를 들어 회의 음성을 글로 정리하는 데 쓸 수 있습니다`는 기능에 관한 설명이다. 해당 기능의 근거가 필요하다.
- `회의 내용을 정리해야 하는 사람이라면 이런 기능을 검토할 수 있습니다`는 사용 상황의 제안이다. 그 사람에게 적합하다고 검증한 결과는 아니다.
- 설명이 길어지면 독자의 목적과 관련된 예시만 남긴다. 독자가 이미 아는 배경 설명을 늘리지 않는다.[8]

## 7. 어휘와 용어를 정확하고 자연스럽게 쓴다

### 7.1 쉬운 말이 더 정확한지 함께 확인한다

낯선 말은 설명하거나 적절한 설명으로 연결한다. 같은 개념에는 일관된 용어를 쓴다.[7]

쉬운 말로 바꾸는 목적은 뜻을 정확히 전달하는 것이다. 전문 용어를 무조건 없애거나 우리말로 바꾸는 것은 아니다. 독자의 배경지식과 사용 맥락에 맞게 선택한다.[2][8]

- 익숙하지 않은 약어는 처음 나올 때 뜻이나 역할을 설명한다. 영문 전체 이름을 풀어 쓰는 것만으로 설명이 충분한지는 따로 판단한다.[7]
- 구별해야 할 개념을 같은 쉬운 말로 뭉뚱그리지 않는다.[7]
- 제품명, 버전명, 명령, 코드, 설정 키 등 식별이 필요한 표기는 임의로 고치지 않는다. 이 보존 규칙은 **자체 구성 기준**이다.
- 맞춤법·띄어쓰기·표기를 검토하되, 오래된 자료의 개별 어휘 교정을 현재의 모든 표기에 그대로 적용하지 않는다. 공공언어 자료의 표현 점검을 바탕으로 한 적용 원칙이다.[3]

### 7.2 번역투와 불필요한 명사화를 줄인다

명사화 때문에 행위가 흐려지면 동사 중심으로 풀어 쓴다. 한국어 문장 교정 자료와 구체적인 서술에 관한 자료를 함께 참고한다.[1][4]

| 흐릿하거나 불필요하게 긴 표현 | 동작이 드러나는 표현 |
|---|---|
| 문서에 대한 검토를 수행한다 | 문서를 검토한다 |
| 설정의 변경을 진행한다 | 설정을 변경한다 |
| 고객 문의에 대한 응답 처리를 지원한다 | 고객 문의에 답하는 일을 돕는다 |

위 표는 **자체 구성한 문장 예시**다. 예를 들어 도구가 직접 답하는지, 답변 초안만 만드는지는 별도로 확인해 구체화해야 한다.

`지원하다`, `제공하다`, `가능하다`, `처리하다`는 금지어가 아니다. 해당 문장에서 무엇을 뜻하는지 충분히 드러나는지가 기준이다. Google의 영어 동사 지침을 한국어의 `이다`나 `있다` 금지 규칙으로 옮기지도 않는다.[6]

## 8. 간결함·톤·구성을 독자에 맞춘다

### 8.1 줄일 때는 군더더기부터 줄인다

의미를 유지하면서 짧게 쓴다. 문장의 연결과 조건을 먼저 점검한 뒤 중복·겹말·불필요한 명사화 등을 줄인다.[1][5]

**남겨야 할 정보**는 독자의 판단을 바꾸는 주체, 동작, 결과, 적용 범위, 조건이다. 글자 수를 줄이기 위해 이를 삭제하지 않는다. 이는 의미 보존 원칙의 **자체 구성 적용 기준**이다.

한 문장에 관계가 너무 많이 들어가면 두 문장으로 나눈다. 다만 모든 문장을 같은 길이로 만들거나 고정된 문장 수에 맞추지는 않는다.

### 8.2 제목과 요약도 같은 정확성 기준을 적용한다

제목을 지나치게 생략하거나 과장하지 않는다. 제목만 읽었을 때 본문과 다른 주체·범위·결과를 떠올리게 하면 고친다.[2]

- 기능의 일부만 해당하면 제목도 전체 기능에 해당하는 것처럼 쓰지 않는다.
- 제목의 모호함을 본문이 해명하도록 두지 않는다.
- 독립된 카드나 요약에서는 이해에 필요한 최소 맥락을 해당 단위 안에 둔다.

위 점검 목록은 제목의 생략·과장 방지 원칙을 정보성 콘텐츠에 적용한 **자체 구성 기준**이다.

### 8.3 자연스러운 말투와 정확성은 양립해야 한다

독자와 글의 목적을 고려하고 자연스러운 표현을 선택한다. Microsoft 자료의 독자·맥락 고려 원칙은 참고하되, 그 회사의 브랜드 말투를 공통 표준으로 채택하지는 않는다.[5]

이 지침은 해요체, 하십시오체, 평서형 중 하나를 모든 글의 필수 말투로 지정하지 않는다. 문장 종결 방식, 친근함의 정도, 표·목록·문단의 배치는 작업별 지침에서 정한다. 이는 **자체 구성 기준**이다.

친근하게 쓴다고 과장하거나 조건을 빼지 않는다. 정확하게 쓴다고 공문서 말투를 강제하거나 명사형 표현만 나열하지 않는다.

## 9. 작성·편집·검수 순서

이 순서는 **자체 구성한 편집 절차**다. 수집·발행 운영 절차가 아니라, 원자료를 글로 옮기는 과정의 기준이다.

1. **독자와 목적을 정한다.** 무엇을 알아야 하는지와 이미 아는 내용을 구별한다.[2][8]
2. **보존할 사실을 정리한다.** 주체, 행위, 대상, 결과, 범위, 조건, 미확인 사항을 적는다. 원자료에 없는 정보를 설명에 보충한다면 근거를 확보한다.
3. **설명 순서를 잡는다.** 독자에게 필요한 내용을 먼저 두고, 낯선 용어와 배경 설명의 위치를 정한다.[2][8]
4. **한국어로 작성한다.** 원문의 단어 배열을 따라가기보다 뜻을 보존하며 자연스러운 문장으로 구성한다.[5]
5. **의미와 조건을 대조한다.** 원자료와 비교하여 추가·누락·방향 변경·범위 확대가 없는지 확인한다.
6. **문장과 어휘를 다듬는다.** 호응, 병렬, 서술어 공유, 수식 범위, 번역투, 용어의 일관성을 점검한다.[1][4][7]
7. **독자 관점에서 읽는다.** 제목과 본문에서 필요한 동작과 관계를 설명할 수 있는지 확인한다.
8. **출처와 확인 범위를 기록한다.** 원자료에서 확인한 내용, 작성자의 해석, 실제 시험 여부를 혼동하지 않게 표시한다.

### 검수와 실제 이해 확인은 다르다

검수자가 이해하기 쉬워 보인다고 판단한 것과 실제 독자가 이해한 것은 같은 증거가 아니다. 독자에게 글을 읽게 하고 의미를 자기 말로 설명하도록 부탁하는 확인 방법은 국립국어원 자료의 환언 검사에 제시되어 있다.[2]

실제 독자 확인을 하지 않았다면 `독자 이해 검증 완료`라고 쓰지 않는다. 대신 `문장·의미 검수 완료`처럼 실제로 한 일을 적는다. 이 표기 구분은 **자체 구성 기준**이다.

피드백에서 이해하기 어렵다는 지적이 나오면 말투만 바꾸지 않는다. **어떤 주체·동작·조건·관계가 전달되지 않았는지** 확인하고 설명을 고친다.

## 10. 최종 점검과 통과 기준

다음은 이 지침의 **자체 구성 검수 기준**이다. 원전의 공식 평가 척도나 독자 실험 결과로 소개하지 않는다.

### 점검표

- [ ] 독자와 글의 목적에 맞는 정보가 들어 있는가?
- [ ] 주체, 행위, 대상, 결과의 관계가 원자료와 같은가?
- [ ] 필수·선택·예외, 범위와 확실성이 보존되었는가?
- [ ] 병렬 요소와 서술어의 연결이 맞는가?
- [ ] 수식어나 지시어가 가리키는 대상이 분명한가?
- [ ] 독자가 모를 용어와 필요한 동작을 설명했는가?
- [ ] 분류명과 기능 목록만으로 설명을 대신하지 않았는가?
- [ ] 제목·요약이 본문과 다른 뜻을 만들지 않는가?
- [ ] 확인하지 않은 사실을 설명이나 예시에 추가하지 않았는가?
- [ ] 맞춤법·띄어쓰기·용어·식별 표기가 맞는가?
- [ ] 출처에 있는 내용, 작성자의 해석, 실제 확인 범위를 구별했는가?

### 판정

| 판정 | 해당하는 경우 | 처리 |
|---|---|---|
| 의미 수정 필요 | 주체·행위·결과·조건·범위가 달라짐 | 원자료와 대조하여 고친 뒤 다시 검수한다 |
| 정보 보충 필요 | 독자에게 필요한 동작이나 관계의 근거가 없음 | 근거를 보충하거나, 설명 범위를 줄이고 미확인 내용을 구별한다 |
| 표현 수정 필요 | 의미는 맞지만 호응·수식·어휘·설명 순서 때문에 이해하기 어려움 | 문장이나 구성을 고친 뒤 의미가 유지됐는지 확인한다 |
| 통과 | 해당 글에 필요한 정보를 정확하고 명료하게 전달함 | 실제로 수행한 검수 범위만 기록한다 |

의미 왜곡이나 중요한 조건 누락이 남아 있으면 통과시키지 않는다. 반대로 특정 종결어미, 문장 길이, 전문 용어의 존재만으로 탈락시키지는 않는다. **독자가 필요한 내용을 정확히 이해할 수 있는지**가 기준이다.
