# 범용 UI/UX 표준 지침

> **문서 상태:** 범용 기준의 초안이다. 문서 등록만으로 개별 에이전트의 실행 지침이 활성화되지는 않는다.

## 적용 상황

사용자 경험을 설계·변경·검수하거나, 그 결과의 적합성을 판단할 때 적용한다. 특정 기능의 도입이나 구현 방식의 채택을 요구하지 않는다.

## 성격과 적용 원칙

이 문서는 서비스의 종류, 사업 영역, 제공 매체, 실행 환경, 특정 기능의 존재와 무관하게 적용할 수 있는 UI/UX 요구사항만 정의한다. 대화에서 반복된 요구를 구현 수단이 아닌 사용자 경험의 원칙으로 추상화한 실무 표준안이며, 공식 인증 규격이나 모든 상황의 최적 해법을 보증하는 문서는 아니다.

- 특정 기능을 반드시 만들도록 요구하지 않는다. 제공하는 경험이 아래 조건을 충족하는지 판단한다.
- 구현 방법·시각 스타일·수치·기술 선택을 고정하지 않는다. 같은 기준을 여러 방법으로 충족할 수 있다.
- 필요한 정보는 필요한 시점에 제공한다. 처음부터 모든 내용을 노출하거나 경험의 의도된 발견까지 설명하라는 뜻은 아니다.
- 구현 결과가 아니라 사용자에게 발생하는 효과를 기준으로 적합성을 판정한다.
- 불필요한 요소는 줄이되 가치·의미·안전·필요한 통제를 훼손하지 않는다.

## 규범

### U01. 목적 적합성

모든 정보와 상호작용은 서비스가 제공하려는 가치와 사용자의 목적에 기여해야 한다.

**적합성 확인**
- 각 요소가 어떤 이해·판단·행동·경험을 돕는지 설명할 수 있다.
- 제공한다고 약속한 가치를 실제 사용 과정에서 얻을 수 있다.

### U02. 정보의 우선순위

정보의 중요도·관계·진행 순서가 필요한 시점에 드러나야 한다.

**적합성 확인**
- 사용자가 현재 필요한 정보와 이후에 필요한 정보를 구별할 수 있다.
- 중요한 내용이 부차적인 내용에 묻히거나 서로 다른 역할의 정보가 혼동되지 않는다.

### U03. 명료한 표현

판단과 조작에 필요한 표현은 사용자가 이해할 수 있는 말로 작성하고, 필요한 의미와 조건을 보존해야 한다.

**적합성 확인**
- 별도의 내부 지식 없이 필요한 대상·행동·조건을 이해할 수 있다.
- 짧게 줄인 표현 때문에 핵심 의미가 누락되거나 불필요한 설명 때문에 핵심이 흐려지지 않는다.

### U04. 의미의 일관성

같은 개념은 같은 의미로 표현하고, 다른 개념은 필요한 만큼 구별해야 한다.

**적합성 확인**
- 이름·표현·값의 해석이 같은 개념을 다루는 과정에서 충돌하지 않는다.
- 표현을 변경해도 관련 정보와 행동 사이의 의미 관계가 유지된다.

### U05. 사실과 안내의 정합성

서비스의 상태·기능·결과에 대한 안내는 실제로 확인된 사실과 일치해야 한다.

**적합성 확인**
- 실제 제공하지 않는 기능이나 사용자가 수행할 수 없는 행동을 가능하다고 안내하지 않는다.
- 확인된 사실·추정·미확인 정보를 구별하며, 관련된 표시 사이의 차이는 설명 가능한 기준을 가진다.

### U06. 처리 상태의 가시성

사용자의 다음 판단에 영향을 주는 처리 상태와 변화는 필요한 시점에 인지할 수 있어야 한다.

**적합성 확인**
- 처리가 수락됐는지, 진행 중인지, 끝났는지 또는 확인할 수 없는지 필요한 범위에서 구별할 수 있다.
- 부재·실패·미확정·실제 결과가 서로 오인되지 않는다.

### U07. 행동의 예측 가능성

행동을 실행하기 전에 조작의 의미·적용 범위·중대한 영향을 이해할 수 있어야 한다.

**적합성 확인**
- 사용자가 선택한 대상과 실행되는 행동의 대상이 일치한다.
- 내용의 창의적 결과나 의도된 발견을 미리 공개하지 않더라도, 조작 자체의 의미와 중요한 영향은 잘못 이해되지 않는다.

### U08. 필요에 비례하는 사용자 부담

목적 달성에 필요한 수준의 입력·선택·기억·반복만 요구해야 한다.

**적합성 확인**
- 이미 유효하게 확보되었거나 서비스가 결정할 수 있는 정보를 이유 없이 다시 요구하지 않는다.
- 필요한 확인과 숙고는 유지하면서 목적에 기여하지 않는 단계와 반복을 줄인다.

### U09. 맥락의 연속성

상호작용이 이어지거나 중단·재개될 때 작업에 필요한 유효한 맥락을 보존하거나 회복할 수 있어야 한다.

**적합성 확인**
- 이전 선택·입력·완료 결과를 이유 없이 잃어 같은 일을 반복하지 않는다.
- 의도된 초기화나 보존할 수 없는 범위가 있으면 이를 인지하고 다음 행동을 판단할 수 있다.

### U10. 사용자 의도와 통제의 보장

서비스는 사용자의 유효한 선택과 동의 범위를 존중하고, 중요한 의사결정을 의도와 다르게 대체하지 않아야 한다.

**적합성 확인**
- 실행 범위와 중요한 변경이 사용자의 선택·승인과 일치한다.
- 중단·변경·취소가 허용되는 범위와 허용되지 않는 제약을 필요한 시점에 이해할 수 있다.

### U11. 오류의 예방

예측 가능한 오해와 잘못된 조작을 줄이고, 중대한 영향이 발생하기 전에 필요한 검증을 수행해야 한다.

**적합성 확인**
- 허용되지 않는 값이나 행동의 조합을 가능한 이른 시점에 식별한다.
- 반복 조작이나 잘못 이해한 실행으로 의도하지 않은 중복·손실이 발생하지 않도록 제어한다.

### U12. 실패 후의 회복 가능성

실패했을 때 영향과 확인 가능한 원인을 알리고, 가능한 회복 경로 또는 다음 조치를 제시해야 한다.

**적합성 확인**
- 무엇이 실패했고 어떤 결과가 남았는지 필요한 수준에서 이해할 수 있다.
- 기존 정보와 완료 결과를 불필요하게 훼손하지 않으며, 불가능한 해결책이나 확인 없는 재실행을 권하지 않는다.

### U13. 인지와 조작의 가능성

중요한 정보와 필수 행동은 의도된 사용자에게 인지·이해·접근·조작 가능한 방식으로 제공되어야 한다.

**적합성 확인**
- 중요한 정보나 필수 행동이 표현·배치·조작의 장벽 때문에 실질적으로 이용 불가능해지지 않는다.
- 특정 표현이나 조작에 의존해 목적 달성이 제한되는 사용자가 있는지 확인하고 대체·보완 가능성을 검토한다.

### U14. 표현과 동작의 일관성

같은 의미와 같은 행동은 예측 가능한 공통 문법을 따르고, 표현의 차이는 실제 의미·기능·우선순위의 차이를 반영해야 한다.

**적합성 확인**
- 같은 종류의 상호작용을 불필요하게 새로 학습하지 않아도 된다.
- 구성이나 상태가 바뀌어도 의미 관계와 조작 단서가 유지되며 의도하지 않은 시각·동작 변화가 없다.

### U15. 관찰 가능한 완료 기준

완료는 구현 여부가 아니라, 사용자의 목적 달성·실제 동작·정보 전달·표현의 적합성을 확인한 결과로 판정해야 한다.

**적합성 확인**
- 기대 결과와 실제 결과를 대조할 수 있는 관찰 근거가 있다.
- 확인한 범위·실패·미확정이 구분되며 일부 성공이나 추정을 전체 검증 완료로 표현하지 않는다.

## 검수와 판정

각 기준은 실제 사용 과정에서 확인한다. 특정 표현 수단이나 내부 구현을 사용했다는 사실만으로 통과시키지 않는다.

### 검수 순서

1. **목적과 범위를 정한다.** 사용자의 목적, 제공하기로 한 가치, 확인할 상호작용의 시작·진행·완료 범위와 허용된 관찰·실행 범위를 확인한다.
2. **기대 결과를 정한다.** 관찰할 결과와 판단에 필요한 근거를 준비한다. 구현된 모습을 기대 결과로 소급 정의하지 않는다.
3. **사용 과정을 관찰한다.** U01~U15의 규범과 각 두 적합성 확인 항목을 함께 읽고, 실제 의미·상태·행동·결과를 대조한다.
4. **기준별로 판정한다.** 두 확인 항목의 결과와 근거를 남긴다. 확인하지 못한 항목이 있으면 해당 기준 전체를 확인했다고 쓰지 않는다.
5. **수정 후 다시 확인한다.** 바뀐 항목과 연관된 경험의 의미·동작이 유지되는지 확인하고 판정 근거를 갱신한다.
6. **확인 범위를 보고한다.** 확인한 결과와 미확인 범위를 구분하고 관찰하지 않은 경험까지 검수 완료로 확대하지 않는다.

### 판정

| 판정 | 조건 |
|---|---|
| 적합 | 관련된 경험이 요구사항을 충족한다는 관찰 근거가 있다. |
| 부적합 | 요구사항을 충족하지 못하는 사용상의 문제가 확인됐다. |
| 미확인 | 필요한 근거가 없거나 확인을 완료하지 못했다. |
| 관련 상황 없음 | 제공 범위에 해당 상황이 존재하지 않음을 설명할 수 있다. |

‘관련 상황 없음’은 특정 기능을 새로 만들 필요가 없다는 뜻이지, 사용자가 겪는 문제를 제외할 수 있다는 뜻이 아니다. 기준 간 충돌이 있으면 목적·의미·안전·통제에 미치는 영향을 함께 검토하고, 선택한 방식이 각 기준을 어떻게 충족하는지 기록한다.

### 기록 양식

| 기준 ID | 사용자 목적 | 관찰한 과정 | 기대 결과 | 실제 결과 | 판정 | 관찰 근거 | 미확인 범위 |
|---|---|---|---|---|---|---|---|

부적합에는 관찰한 문제와 수정할 내용을, 미확인에는 확인하지 못한 범위와 이유를 기록한다. 관련 상황이 없다는 판정에도 그 근거를 남긴다.

### 검수 완료와 적합 판정

U01~U15의 확인 항목을 점검하고 기준별 판정·근거·미확인 범위를 기록하면 검수 기록을 완료할 수 있다. 검수 기록의 완성과 서비스의 적합 판정은 다르다. 부적합이 남아 있거나 필요한 확인이 끝나지 않았다면, 기록이 완성됐다는 이유로 적합하다고 보고하지 않는다.

### 판단이 어려울 때

- **관찰할 수 없음:** 미확인으로 기록하고 필요한 근거를 확보한다. 추정으로 통과시키지 않는다.
- **기대 결과가 불명확함:** 사용자 목적과 기준의 의미를 먼저 확인한다.
- **여러 기준이 충돌함:** 목적·의미·안전·통제에 미치는 영향을 함께 검토한다. 충족 여부를 확인할 수 없는 기준은 미확인으로 남긴다.
- **수정 후 다른 문제가 발생함:** 바뀐 기준과 관련 경험을 다시 확인하고 판정 근거를 갱신한다.

## 완료의 정의

사용자가 의도된 가치를 얻을 수 있고, 필요한 정보를 이해하며, 행동과 결과를 구별하고, 불필요한 부담이나 오인 없이 경험을 이어갈 수 있다는 사실이 확인돼야 한다. 구현 의도와 실제 경험이 다르면 실제 경험을 기준으로 수정한다.

## 판단 근거

사용자 피드백에서 목적·의미·상태·통제·회복·검증에 관한 요구를 추리고, 특정 서비스나 실행 환경의 전제가 없어도 의미가 유지되는 수준으로 일반화해 직접 작성했다. 규범, 적합성 확인 항목, 검수·판정·기록 방법은 이 문서를 위한 자체 구성이다.

특정 기능·구성 요소·제공 매체·구현 기술·시각 수치를 채택 조건으로 삼지 않는다. 관찰 가능한 사용자 경험의 효과를 판단 기준으로 삼는다. 이 문서는 외부 기관의 공식 규격을 인용한 인증 기준이나 모든 상황의 최적 해법을 보증하는 문서가 아니다. 비공개 대화 원문과 식별 가능한 업무 자료는 공개 문서에 포함하지 않는다.
