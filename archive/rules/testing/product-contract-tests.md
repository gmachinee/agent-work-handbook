# 제품 계약 중심 테스트 기준

> 보관 문서입니다. 현재 기준은 [소프트웨어 변경·검증 기준](../../../knowledge/rules/coding/engineering-changes.md)에 통합했습니다. 아래 내용은 과거 기준이며 활성 규칙이 아닙니다.

## 적용 상황

제품 테스트를 작성·수정·정리하거나 업무 흐름의 테스트 자동화를 구현할 때 적용한다. 공통 변경·검증 원칙은 [에이전트 사용 기준](../../../AGENTS.md)을 따르며 여기서 반복하지 않는다.

## 기준

- 테스트 개수를 억지로 줄이거나 늘리지 않는다. 실제 제품 계약과 사용자 동작을 검증하는 데 필요한 만큼 작성한다.
- 같은 의미를 반복하는 검사는 정리하되, 서로 다른 회귀 위험을 방어하는 테스트는 유지한다. 테스트를 제거할 때는 어떤 계약·위험의 검증이 남는지 확인한다.
- 테스트를 위해 제품 코드를 불필요하게 확장하거나, 업무 구현을 복제한 테스트용 구조를 만들지 않는다.
- 업무 흐름 자동화는 실제 제품에서 사용하는 업무 코드를 호출한다. 복사한 로직의 성공을 제품 동작의 검증으로 삼지 않는다.

## 예외와 조건

외부 의존성을 모의 처리하는 것과 검증 대상 업무 로직을 복제하는 것은 다르다. 모의 처리는 검증 범위를 명시하며, 그 결과를 실제 연동 성공으로 해석하지 않는다. 이 기준은 필요한 제품 코드 변경이나 테스트 경계 분리를 전면 금지하지 않는다.

실행할 테스트 범위는 변경의 영향과 프로젝트 기준으로 정한다. 테스트 개수 감축 목표나 영향 범위 밖 테스트의 일괄 실행 금지를 뜻하지 않는다.

## 판단 근거

소유자가 여러 개발 작업에서 직접 제시한 테스트 작성 원칙과, 자동화에서 실제 제품 코드를 복제하지 않고 호출하라는 요구를 정리했다. 대화 검토 후 중복을 제외한 반영안을 소유자가 승인했다. 비공개 대화 원문과 업무 식별자는 포함하지 않는다.
