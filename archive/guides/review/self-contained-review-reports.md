# 자기 완결적 검수 보고서 구성

> 보관 문서입니다. 현재 검수 보고서 구성은 [UI/UX 통합 지침의 최소 기록](../../../knowledge/rules/design/universal-uiux.md#최소-기록)을 따릅니다. 검증 자산 관리는 [소프트웨어 변경·검증 기준](../../../knowledge/rules/coding/engineering-changes.md#6-검증-자산의-재사용관리)에 통합했습니다. 아래 내용은 과거 기준이며 활성 규칙이 아닙니다.

## 적용 상황과 경계

사용자 흐름의 구현 결과를 검수 보고서로 전달할 때 적용한다. UI/UX의 기대·실제 결과, 관찰 근거, 판정·완료 기준은 [UI/UX 통합 설계·검수 지침의 최소 기록](../../../knowledge/rules/design/universal-uiux.md#최소-기록)을 따른다. 이 문서는 그 기준이나 검수표를 복제하지 않고 보고서의 배치·연결 방식만 다룬다.

## 작업 순서

1. 파일·커밋 순서가 아니라 검수할 유저 스토리별로 결과를 묶는다.
2. 각 검수 단위나 페이지에 유저 스토리, 사전조건, 실행한 행동, 화면에서 확인할 위치를 적는다. 전체 보고서의 공통 환경은 한 곳에 적고 해당 단위에서 연결한다.
3. 해당 단위의 기대·실제 결과, 판정, 관찰 근거와 근거 범위를 같은 맥락에서 확인할 수 있게 연결한다. 이미 작성한 기준별 결과를 다시 별도 표로 복제하지 않는다.
4. 스크린샷을 사용하면 어느 위치가 어떤 결과를 입증하는지 설명한다. 화면만으로 입증하지 못하는 서버 처리·데이터 반영은 해당 증거와 구분한다.
5. 대화 이력을 모르는 검토자가 각 단위에서 무엇을 실행했고 무엇을 확인했는지 판단할 수 있는지 확인한다.

## 산출물 범위

모든 작업에 별도 보고서·PDF·스크린샷을 강제하지 않는다. 기존 설계 문서나 결과 보고가 같은 역할을 충족하면 그 위치를 사용한다.

일회성 검수 보고서·이미지·생성 스크립트와 지속 유지할 회귀 테스트 자산을 구분하고, 저장·버전 관리 범위는 프로젝트 기준과 현재 요청에서 정한다. 모든 E2E 리소스를 PR에서 일괄 제외하지 않는다.

## 판단 근거

소유자가 여러 검수 작업에서 요구한 유저 스토리 기준 구성과 페이지별 자기 완결성을 정리했다. 일회성 보고 자료의 PR 제외 요구와 E2E 스크립트 유지보수 요구를 구분한 반영안을 소유자가 승인했다. PDF 형식이나 특정 기기·언어·테마는 공통 의무로 확장하지 않는다.
